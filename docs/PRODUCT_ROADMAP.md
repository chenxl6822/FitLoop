# FitLoop 用户体验路线图

更新时间：2026-08-13

## 1. 产品结论

FitLoop 仍需要持续完善，但优先级不应由“技术是否炫酷”决定，而应由用户能否更轻松地开始、坚持并信任一次运动决定。本轮把原本分散的打卡、统计和 AI 能力串成了可完成的用户闭环：

1. 跑步前：首次使用引导、定位与地图隐私分级同意。
2. 跑步中：实时轨迹、本地预览、道路底图、弱网安全队列。
3. 跑步后：本人历史轨迹、周统计、目标进度和异常申诉。
4. 下一次训练：首页直接显示并完成 AI 训练计划的今日项目。
5. 长期信任：解释数据用途、导出自己的数据、验证密码后注销账号并撤销会话。

地图并不是不能加入。本轮已经加入实时与历史地图；未直接使用地图厂商 SDK，是为了避免在没有隐私同意和密钥治理的情况下扩大敏感定位数据暴露。当前实现允许用户只记录轨迹而不加载第三方道路底图，并把地图瓦片地址做成可替换配置。

## 2. 同类产品调研与取舍

| 产品 | 公开产品能力 | 用户价值 | FitLoop 的取舍 |
| --- | --- | --- | --- |
| Keep | 户外跑步、路线、课程、社区和记录分享；公开 ESG 材料还披露了创建/参考路线及同路线对比 | 降低运动内容选择成本，路线与社区增强坚持感 | 本轮先完成可靠记录、本人轨迹和今日训练；公共路线在隐私、审核与地图授权完成前不开放 |
| Nike Run Club | 面向不同水平的训练计划，每周和每次跑步都解释目标，支持音频引导 | 用户不需要先掌握专业术语，也知道“今天练什么、为什么练” | 本轮把训练计划变为首页可执行任务；后续优先补训练原因、语音/震动提示和计划调整 |
| Strava | 路线创建、社区热度驱动的路线推荐、训练统计、目标与隐私控制 | 适合探索路线和复盘表现，但路线推荐依赖更大规模的活动数据与安全治理 | 不在冷启动阶段伪造“智能路线推荐”；先积累匿名、获同意且质量合格的数据，再做校园安全路线 |

## 3. 本轮已交付

### P0：运动记录必须可信

- GPS 跑步实时轨迹和道路底图；底图需单独隐私同意。
- 历史运动仅本人可读取轨迹，避免通过记录 ID 越权查看。
- 离线队列不持久化 access token，旧队列迁移并支持失败重试。
- Agent 工具调用预算在并发情况下原子执行，避免重复写入或超预算。

### P1：让用户每天知道下一步

- 首页显示下一项训练、类型、时长、强度、说明与完成进度。
- 完成训练日操作幂等，重复点击不会重复累计。
- 既有提醒、周统计、排行榜、好友、申诉和反馈入口继续保留并纳入回归。

### P1：建立数据信任

- 应用内解释轨迹、健康数据、AI 建议和第三方地图请求的边界。
- 用户可导出资料、运动、轨迹、目标、健康、提醒、社交、申诉、反馈和训练计划；不导出密码和令牌。
- 用户输入当前密码后可注销：业务数据删除、联系方式匿名化、刷新令牌撤销，旧 JWT 立即失效。

## 4. 上线门禁

只有以下门禁全部满足，才可以把对应能力标记为“已上线”：

- 后端：JDK 21、全量单元/集成测试、JaCoCo 门禁、MySQL 8 迁移与 JPA 校验通过。
- 移动端：`flutter analyze`、全量测试、release 编译通过。
- 部署：备份成功、Compose 配置通过、服务健康检查通过、核心 API 冒烟通过。
- APK：API 使用 HTTPS；签名证书与现有公开 APK 兼容；APK、SHA-256 和版本元数据一致；至少一台真机验证定位、锁屏/前后台、弱网重试、地图和升级安装。
- 发布：PR 审查与 CI 通过后合并；服务器只部署 `main` 的确定提交；失败时能回滚数据库前备份、服务镜像和 APK。

仓库现有 `0.1.7+8` 是被严格锁定的短期 HTTP 过渡版本，不能复用于后续公开版本。没有 HTTPS 和受信签名证据时，只能证明“代码和构建已就绪”，不能宣称 APK 已安全公开上线。

## 5. 后续开发计划（以用户指标决定是否进入下一阶段）

### 阶段 A：两周内完成发布可观测性

目标：用户能成功完成第一次跑步，团队知道失败发生在哪里。

- 事件仅记录必要状态，不采集完整轨迹：定位授权结果、开始/完成、队列重试、地图同意、今日训练完成、导出/注销成功率。
- 核心指标：首次跑步完成率、跑步完成请求成功率、离线队列 24 小时清空率、崩溃率、地图加载失败率。
- 护栏：不得把手机号、令牌、完整经纬度或健康备注写入分析事件。

### 阶段 B：4–6 周改善坚持体验

进入条件：首次跑步闭环稳定，失败率达到发布目标。

- 训练前显示“为什么今天这样练”，并允许因疲劳、天气或时间不足调整。
- 跑步中提供可关闭的公里语音/震动提示、暂停恢复和偏离目标提醒。
- 跑步后给出配速分段、与自己同路线历史对比和可执行恢复建议。
- 指标：次周留存、计划训练完成率、提醒关闭率、训练调整后完成率。

### 阶段 C：6–10 周接入系统健康数据

进入条件：完成 Android 真机矩阵和敏感数据影响评估。

- 使用 Android Health Connect 的细粒度、按需授权；默认只读用户明确选择的步数、活动和体重类型。
- 提供同步来源、最后同步时间、单项撤权和冲突处理，不做静默全量上传。
- 指标：授权后同步成功率、重复记录率、撤权成功率、健康页使用率。

### 阶段 D：10–16 周验证校园安全路线

进入条件：获得足够、获同意且质量合格的匿名路线数据，并建立内容审核和安全投诉流程。

- 先做人工运营的校园推荐路线：照明、开放时间、距离、坡度和风险提示。
- 再以小流量实验路线规划，不宣称绝对安全，不公开个人起终点和高频住址。
- 指标：路线开始率、完成率、偏航率、投诉率和安全事件；任何安全 P0 立即下线路线推荐。

## 6. 当前不做

- 不在缺少真机验证时直接接入 Health Connect 并宣称可用。
- 不在缺少路线规模与审核时模仿 Strava 生成公共路线。
- 不把 AI 建议描述为医疗诊断或强制计划。
- 不为追求“社交活跃”默认公开轨迹、学校、起终点或健康数据。
- 不用跳过测试、测试签名、明文 HTTP 或关闭安全门禁换取表面上的上线速度。
